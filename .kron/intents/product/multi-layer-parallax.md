# 备选方向：多层 2.5D 视差

> 状态：**已记录，暂不推进**（2026-11-01）。
> 记录原因：数据表明它可能比「点云环绕」更适合插画，先留档，等主线跑通再评估。

## 为什么值得记一笔

`scripts/analyze-depth.py` 对 float32 原始深度的量化分析显示，**分层比我原以为的可靠，而且不止两层**：

| 输入 | 主体vs背景分离度 | 三层聚类均值 | 三层占比 |
|---|---|---|---|
| 厚涂141118021（田野） | **0.885** | 0.61 / 2.79 / 5.05 | 47% / 23% / 30% |
| 平涂134481384 | **0.914** | 0.38 / 0.55 / 1.19 | 34% / 15% / 51% |
| 平涂131905131 | 0.764 | 0.40 / 0.69 / 1.17 | 41% / 16% / 43% |

同时**主体内部几乎没有结构**（`sub_iqr/幅宽` 仅 0.007~0.06）。

这个组合正好指向一个方向：**把深度按阈值切成 3~5 层，各层以不同速率随鼠标/陀螺仪位移**，
效果接近 Live2D / 3D Photo 的视差动画。

## 为什么它可能比点云环绕更强

| 维度 | 点云环绕 | 多层 2.5D 视差 |
|---|---|---|
| 对深度的要求 | 需要主体内部有几何 | **只需要分层可靠**（已验证） |
| 穿帮风险 | 转到侧面露板 | **不存在**（永远正视角） |
| 和插画的契合 | 要求插画有它没有的 3D 信息 | **插画本来就是分层的**（人物/中景/背景） |
| 实现成本 | 反投影 + 点云 + 着色 | 分层 + 位移，甚至不需要点云 |
| 输出形态 | 可交互网页 | 网页 + 动图，都容易 |

## 但不急着做的理由

1. 主线的点云风格渲染已经跑通，沉没成本不该浪费
2. 多层视差和点云风格**不冲突**——同一份深度可以做两种呈现，共用同一条管线
3. 现在缺的是"端到端跑通"，不是"再加一个方向"

## 真要做时怎么切

最小实现（约 1~2 天）：
1. 深度 → 按分位数切 N 层（N 可调 3~6），每层用形态学补洞避免"剪纸片"边缘
2. 每层用原始插画对应的像素作为贴图，按层序偏移
3. 层间位移量 = 层深度差 × 系数（可调）
4. 鼠标/陀螺仪驱动，而非自由相机
5. 层间遮挡用 mask 处理（前层盖后层）

## 与现有意图的关系

- 依赖 `product/depth-go-no-go` 的实测结论
- 与 `render/style-layering/density-as-style` 无冲突：一个管"点怎么画"，一个管"层怎么动"
- 若实现，`arch/three-way-split` 的三段式不变（Python 出深度、Go 分层、浏览器渲染）

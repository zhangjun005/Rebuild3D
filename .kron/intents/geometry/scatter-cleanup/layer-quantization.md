# 深度层量化：消除层间"拉丝"散落点云

> > 同时是 `product/multi-layer-parallax` 的地基。

已实现于 `internal/pipeline/layers.go`。

## 问题（2026-11-01 实测）

对 100 万点点云做 k-means 分层：三层中心 `d = 0.350 / 0.686 / 1.191`，
但 **16.9%（16.9 万点）落在层间**（距最近层中心 > 0.08）：

| 阈值 | 散落点占比 |
|---|---|
| > 0.08 | 16.9% |
| > 0.12 | 9.1% |
| > 0.15 | 5.2% |

**关键证据**：这些点的空间位置

| | \|x\| 中位数 | \|y\| 中位数 |
|---|---|---|
| 散落点 | **0.215** | **0.230** |
| 层内点 | 0.662 | 0.401 |

→ 集中在画面中心，**也就是人物周围**。不是随机噪声，是人物边缘被"拉丝"。

### 根因

```
DA3 在插画上输出的是连续深度（不是几块干净的板）
主体与背景之间有一条"过渡尾巴"
  → 反投影后落在两层之间的中间 z
  → 但 x/y 仍贴着人物轮廓
  → 形成"从人物拖向背景的丝状点云"，侧视 30° 时非常明显
```

## 做法

在 `Build` 的「边缘剔除之后、反投影之前」插一步：

1. 对有效深度做一维 k-means（k 可配，默认 3）得到层中心
2. 每个像素硬性归到最近层
3. **每层做 4 邻域连通域分析**，每个连通块取自己的深度中位数
4. 块内像素深度改写为该中位数；小于 0.02% 的碎块并入本层全局中位数

## 为什么人物不会被切开

**层是按连通域划分的，不是按深度值区间切的。**

| 分层方式 | 会不会切开人物 |
|---|---|
| ❌ 按深度值区间 | 会——人物跨深度就被切 |
| ✅ 按连通区域 + 区域取一个深度 | **不会**——人物是连通块，整体一个深度 |

代价：真正跨深度的部位（如伸出的手）会被拉回主体深度。可接受。

## 实测效果

| 指标 | 关闭 | 开启(3层) |
|---|---|---|
| 层间散落点 | 16.9% | **0.9%**（降 95%） |
| 散落点绝对数 | 169,178 | 8,714 |
| 唯一深度值 | 91,991 | **6,574** |
| 画质（平均像素差） | — | 6.9/255 |
| 非纸色占比 | 28.3% | 28.0% |
| 几何耗时 | 534 ms | 762 ms（+43%） |

侧视 30° 对比：关闭时人物周围一圈纤维状拉丝；开启后干净。

## 接口

- `pipeline.Params.LayerCount`：0 = 关闭（库层默认，保持老行为），2~8
- `pipeline.DefaultLayerCount = 3`，**HTTP API 默认开启**
- `/api/infer` 参数 `layer_count`
- meta：`layerCount` / `layerCenters` / `layerFlattened` / `layerComponents`

## 与 multiplane 的关系

这一步的产物 —— **层归属 + 连通块** —— 正是 `product/multi-layer-parallax` 需要的输入。
所以它不是临时补丁，是地基。

## 什么时候该调

- 层数：3 层适合大多数插画；主体复杂（人物+道具+背景）可用 4~5
- 若出现"人物被压到平面"的观感 → 说明该图主体内部确实有深度，考虑关闭层量化
- 小碎块阈值（0.02%）若在大图上导致细节丢失，可调低

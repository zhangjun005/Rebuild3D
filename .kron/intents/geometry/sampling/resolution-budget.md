# 分辨率预算是「双闸门」：process_res 与 max_points 必须一起提

> 实测发现：我们一直在自愿扔掉 7 倍的可用分辨率，而显存根本装得下。

## 点数与原图像素的关系（实测）

| 插画 | 原图 | 原图像素 | 深度图 | 深度像素 | 占原图 |
|---|---|---|---|---|---|
| 平涂131905131 | 4000×4000 | 16,000,000 | 504×504 | 254,016 | **1.59%** |
| 平涂134481384 | 2500×3750 | 9,375,000 | 336×504 | 169,344 | 1.81% |
| 厚涂125626090 | 1632×2456 | 4,008,192 | 336×504 | 169,344 | 4.22% |
| 厚涂149101244 | 1575×2036 | 3,206,700 | 392×504 | 197,568 | 6.16% |
| sample-watermark | 1500×1004 | 1,506,000 | 504×336 | 169,344 | 11.24% |
| sample-manga | 1474×1010 | 1,488,740 | 504×350 | 176,400 | 11.85% |

**公式：**

```
深度边长 = round_to_14(原图边长 × process_res / 长边)     ← 14 是 DINOv2 的 patch
深度像素 = 宽 × 高
点数     = 深度像素 − 边缘剔除 − 体素下采样               ≤ max_points

点数 / 原图像素 ≈ (process_res / 原图长边)²
```

**关键结论：原图越大，点云占原图比例越低。** pixiv 常见的 4000px 作品最吃亏（1.59%）。

## 显存实测：提到 1344 都装得下

| process_res | 深度像素 | 推理耗时 | 峰值显存 |
|---|---|---|---|
| 504 | 254,016 | 0.91 s | 2160 MiB |
| 756 | 571,536 | 1.16 s | 2524 MiB |
| **1008** | 1,016,064 | 2.25 s | **3027 MiB** |
| 1344 | 1,806,336 | 3.72 s | 3919 MiB |

**像素 ×7.1，显存只 ×1.8**（模型用 autocast，激活值增长温和）。8GB 上到 1344 还有 4 GB 余量。

## max_points 的实际档位（2026-11-01 实测，res=1008）

| | 20 万点 | 60 万点 |
|---|---|---|
| workRes | 775 | **1342** |
| edgePointRatio | 0.1975（已到上限） | 0.1537 |
| **强边缘点绝对数** | 39,821 | **92,241（2.3×）** |
| ILC1 | 2.86 MB | **8.58 MB** |
| 推理 | 985~1299 ms | 696~1687 ms（波动大） |
| 几何 | 258~276 ms | 386~416 ms |
| 传输（localhost） | ~35 ms | **38 ms** |
| 解析 + 入库 | 35 ms | 38~39 ms |
| JS 堆增量 | ~13 MB | +14.8 MB |
| **帧率** | 144 | **144（8 次采样全 144）** |

**结论：60 万点完全不掉帧。** 144fps 是 vsync 上限，600k 单 draw call 的顶点开销在这个规模不是瓶颈。

所以"提不提档"不是帧率问题，而是**传输 / 几何 / 内存**问题——而这三项在 60 万档也都可接受：
- 传输 8.58 MB 在 localhost 38 ms（千兆局域网约 70 ms）
- 几何 +140 ms，但推理波动更大，端到端基本没变慢
- 只多 +15 MB JS 堆

## 档位建议

**60 万作为高画质档是可用的，不设上限障碍。** 但注意一个反向权衡：

点数从 20 万 → 60 万时，`edgePointRatio` 从 0.1975 **降到** 0.1537——因为边缘像素数有上限，
多出来的点全部分配到平坦区。对「墨/纸系」风格，**背景变密会让画面更像点云照片、更不像版画**，
而且**主体/背景对比会变弱**（实测：20 万档背景是一坨黑、主体留白，对比强；60 万档背景变均匀浅灰，
figure-ground 反而模糊）。

**所以档位不是"越多越好"，要按风格分：**
- 要「点云立体感」→ 60 万
- 要「版画/点画的纸感」→ 20~40 万，甚至更少

## 不要误用

提 `process_res` **不会让深度更准**（见假设 `depth-semantics-resolution-independent`）。
它只增加「可选点的精度」。别拿它当画质旋钮。

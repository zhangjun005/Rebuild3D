# 02 · 方向扩充：跳出家居还能往哪走

> 状态：分析完成，待决策
> 问题：这个需求能不能不局限家居，改到别的方向

---

## 结论

**能换，但换的不是"行业名"，而是"精度档位 + 交付格式"。**

行业名是最表层的标签。同一套引擎（多视图 → 米制深度 → 点云/平面 → 浏览器编辑 → GLB）放到文保、游戏、二手交易、教育，技术上都能跑；但它成不成，只由两件事决定：

1. **这个方向要求的精度档位，是不是在我们能到的那两档之内**
2. **这个方向真正要的交付物，是不是我们能产出的那个**

所以下面不按"行业"排，按**"离我们现有主链路差几步"** 排。

---

## 一个反直觉的结论：客户要的从来不是 3D

做家居也好，做文保也好，付钱的人要的几乎都不是"一个 3D 模型"。他们要的是 3D 能产出的那张**二维图**：

- 装修/设计 → **平面图**（进 CAD）
- 房产 → **户型图**（进宣传物料）
- 文保 → **立面图 / 测绘图**（进档案）
- 游戏/影视 → 反过来，真要 3D，但只要能拖进 DCC 的**参考粗糙体量**

只有游戏/影视那一类是真的要 3D 本身。

这才是"热度退了"的更底层解释：**大家做出来的点云，没有下游能接**。

所以方向扩充有两个方向，成本差 10 倍：

| 扩张方式 | 含义 | 成本 | 复用率 |
|---|---|---|---|
| **横着换行业** | 家居 → 文保/二手/教育 | 高（输入和输出都变） | 低 |
| **纵着往下游走一步** ✅ | 点云 → 平面图 → 报价单；点云 → GLB → DCC | 低（只加最后一步） | 高 |

**优先做纵的。** 下面五个方向里，A 和 C 是纵向的，B/D 是横向的，E 是逃生舱。

---

## 四条判据

| 判据 | 我们能做到 | 越界就死 |
|---|---|---|
| **精度档位** | 观感级 ✅ / 体量级 ✅（勉强）/ 尺寸级 ⚠️（靠米制模型+验证）/ 施工级 ❌ | 要"能施工""能验收""能测绘" |
| **输入成本** | 手机随手拍 3~6 张 ✅ | 要求标定相机、多相机阵列、激光扫描仪 |
| **交付格式** | GLB ✅ / PLY ✅ / 平面图 SVG-DXF ✅（v2）/ 带材质网格 ❌ | 要求 PBR 材质、UV、拓扑 |
| **部署形态** | 本地单机 ✅ | 要求云端多租户、实时协作、SaaS 计费 |

**最重要的一条判据**：任何要求"和卷尺/激光测距仪比精度"的方向，立刻放弃。这不是工程努力能补的，是单目深度的物理上限。

---

## 五个候选方向

### A. 往下游走一步：点云 → 平面图（**最推荐**）

| 项 | 内容 |
|---|---|
| 做什么 | 重建点云之后，自动提取主平面、正交化（Manhattan world）、投影成 2D 线段 → **SVG / DXF 平面图** |
| 输入 | 不变（手机照片 3~6 张） |
| 新增交付 | 平面图（这才是设计师/装修/物业/消防真正能用的东西） |
| 谁付钱 | 装修业主、独立设计师、二手房中介、物业 |
| 8GB | ✅ 平面图**不需要稠密点云**，反而可以降分辨率，更轻 |
| 技术 | 经典方法就够：RANSAC 主平面 → 正交化 → 投影 → 线段拟合。**不需要新模型**。已有成熟参考：[RoomFormer](https://github.com/ywyue/roomformer)（CVPR'23，3D 扫描 → 平面图）、[Manhattan-World CAD 生成](https://github.com/joyjo/to-generate-2D-floorplan-CAD-from-3D-point-clouds)、[相关论文](https://www.mdpi.com/2076-3417/10/8/2817) |
| 风险 | **输入不匹配**：上述工作都吃稠密激光点云，我们吃的是单目多视图的稀疏深度。精度会差一截 |
| 增量成本 | **约 2 天**（Go 侧加一个 `geometry/floorplan` 包） |
| 验证方式 | 先做最笨的版本：投影到地面 → 找主方向 → 画外轮廓 → 和人眼对比。**这个 2 天就能知道行不行** |

**为什么最推荐**：它是唯一一个"增量成本极低、交付价值跃升"的方向。点云没人要，平面图人人都要。而且它天然把"精度要求"抬到"尺寸级"——正好是我们米制模型能打的档位，不是施工级。

---

### B. 横着换对象：场景 → 单品转台（turntable）

| 项 | 内容 |
|---|---|
| 做什么 | 绕一件物品拍 20~30 张 → 出一个可 360° 转的物品 |
| 交付 | GLB（带颜色点云，或 v2 转 mesh） |
| 谁付钱 | 二手奢侈品、收藏品（模型/手办/球鞋）、电商、游戏道具参考 |
| 8GB | ✅ 单物体、多视图、可分批 |
| 风险 | **卖相**。点云转起来不如 3DGS 好看，而 3DGS 的 GS head 在 CC BY-NC 的 GIANT 系列上（8GB 装不下）。带材质的网格又跑不动 TRELLIS/Hunyuan3D |
| 增量成本 | 低（同一条链路，换个预处理：自动分割出主体） |
| 判断 | **技术可行但"产品力"不够**。适合当 v2 的顺手功能，不适合当主线 |

---

### C. 横着换付费方：参考采集工具（游戏/影视/DCC）

| 项 | 内容 |
|---|---|
| 做什么 | 不追求交付质量，追"快"和"能进 DCC"。20 张照片 5 分钟出 GLB，直接拖进 Blender / UE 当体积参考、构图参考、灯光参考 |
| 输入 | 不变 |
| 交付 | GLB（唯一要求：进得去引擎） |
| 谁付钱 | 独立开发者、小型游戏/影视工作室、概念设计 |
| 8GB | ✅ 完全够（他们要的就是快和糙） |
| 竞争 | Polycam / Luma / RealityCapture 都在，但都是订阅/云。**"本地 + 一次性 + 单二进制"是差异化** |
| 增量成本 | **接近 0**（就是 v1 本身，只换包装和文档） |
| 判断 | **最贴合你的技能栈**（目标用户接受 CLI）。但市场小、付费意愿弱，不适合当生意，适合作 v1 的对外定位 |

---

### D. 横着换客户：数字存档（文保 / 博物馆 / 学校）

| 项 | 内容 |
|---|---|
| 做什么 | 文物、老建筑、遗址的低成本三维记录 + 浏览器访问 |
| 输入 | 不变（多张照片） |
| 交付 | GLB + 点云 + 剖面图 |
| 谁付钱 | 博物馆、文保单位、高校考古/建筑院系 |
| 8GB | ✅ |
| 优势 | **"全程本地、数据不上云"在这个领域是真需求**（文物数据不许上云），而我们天生是本地架构 |
| 风险 | 采购周期以"年"计；对文档、报告、长期保存格式的要求远超一个工具能覆盖 |
| 增量成本 | 中（要补导出格式、元数据、报告） |
| 判断 | 需求最真、但节奏最慢。适合"有缘再说"，不适合当第一站 |

---

### E. 逃生舱：干脆不碰 3D，只做深度

| 项 | 内容 |
|---|---|
| 做什么 | 不出场景，只出深度图/视差序列。应用：老照片 2.5D 动画、图片分层（前景/背景分离做视差）、浮雕、AR 遮挡 |
| 8GB | ✅ 单图，最轻 |
| 竞争 | ComfyUI 的 DA3 节点已经有人做了（`ComfyUI-DepthAnythingV3`），社区生态比我们快 |
| 判断 | **纯工具，不是产品**。反而是最容易出"能用的东西"的路线，适合在主线卡住时当保底 |

---

## 汇总

| 方向 | 扩张方式 | 增量成本 | 交付价值 | 8GB | 推荐度 |
|---|---|---|---|---|---|
| **A. 平面图** | 纵（下游一步） | **~2 天** | 高 | ✅ | ★★★★★ |
| **C. 参考采集** | 横（换付费方） | ~0（就是 v1） | 中低 | ✅ | ★★★★ |
| B. 单品转台 | 横（换对象） | 低 | 中 | ✅ | ★★☆ |
| D. 数字存档 | 横（换客户） | 中 | 高但慢 | ✅ | ★★ |
| E. 纯深度 | 退化 | 极低 | 低 | ✅ | ★（保底） |

---

## 推荐的扩张顺序

```
v1  场景重建 + 浏览器编辑 + GLB          ← 先把纵向主干打通（约 2 周）
v1.1 加平面图导出（方向 A）               ← 增量 2 天，价值跃升最大
v1.2 包装成"参考采集工具"（方向 C）        ← 只是文档 + CLI 打磨，接近 0 成本
v2  点云 → mesh（补上"带材质的网格"这一环）  ← 才轮到 B / D
```

**关键**：不要一开始就选行业。**先把"纵向主干"打通，再让方向自然长出来。** 因为主干打通后，A 只要 2 天、C 只要 0 天；而如果一开始就去做 B 或 D，主干还没稳就要同时应付新输入格式，两头都会烂。

---

## 明确不要去的地方

| 方向 | 为什么不去 |
|---|---|
| 工程测量 / 施工验收 / 测绘 | 精度档位差 2 档，物理上补不回来 |
| 自动驾驶 / 机器人仿真 | 需要稠密语义 + 高精度 + 实时，三重越界 |
| 电商产品级渲染 | 需要 PBR 材质 + UV + 拓扑，等于要 mesh + 材质生成能力（8GB 装不下 TRELLIS/Hunyuan3D） |
| 房产 3D 展示（Matterport 的领域） | 对方是 LiDAR + 专业相机 + 成熟云端，我们观感级打不过 |
| 医疗 / 牙科 / 义肢 | 精度和合规都越界 |
| 任何"输入是激光点云"的项目 | 那不是我们的护城河。**我们的护城河恰恰是"输入只是手机照片"** |

---

## 一条决策规则（以后纠结时用这一条）

> **只有当扩张能"复用现有主链路、并且只增加下游一步"时，才做。**
> 需要改输入格式、需要加第二个模型、需要和激光比精度的扩张，一律推后。

---

## 待你决定的三件事

1. **v1 的对外定位**取哪个：自用工具 / 参考采集工具（C）/ 先不谈定位只做主干
2. **平面图（方向 A）要不要写进 v1 范围**，还是留作 v1.1（倾向后者：先证明主链路）
3. **平面图的精度目标**：只要"看得出户型"（观感+尺寸的及格线），还是要"误差 < 5%"（尺寸级）

# 03 · 点云质量、风格渲染，与"单图"路线

> 状态：技术分析
> 背景：v1 定的是"多视图 → 米制点云 → 浏览器编辑"（见 [01](01-product-v1.md)）。
> 本文回答两个衍生问题：**点云为什么看起来差、能不能做风格化渲染、单张插画行不行。**

---

## 1. "像素多少就多少点 → 质量不高"，这个判断需要修正

### 1.1 点数不是病灶

"1 像素 1 点"确实是旧管线的做法，但它只是**表象**。真正的四个病灶：

| # | 病灶 | 机理 | 后果 |
|---|---|---|---|
| 1 | **采样与表面无关** | 像素是均匀网格，3D 点间距 ∝ 深度。近处点距 2mm，远处 5cm | 近处堆积、远处稀疏，配不上"表面" |
| 2 | **单视图只有一面** | 这是所有单目方法的物理上限，不是噪声 | 一转视角就穿帮，永远补不回来 |
| 3 | **深度误差是低频的** | DA2 输出相对深度（disparity 体系），误差呈低频弯曲而非独立噪声 | 反投影后表面起伏；深度不连续处出现 "flying pixels"（前景背景被错误连成桥） |
| 4 | **没有置信度** | 无法区分"测得准"和"瞎猜" | 只能全局保留，噪声和信号一起进点云 |

### 1.2 DA3 改了什么（诚实版）

**改了的：**

| 改进 | 依据 |
|---|---|
| 输出 **confidence 图** | `prediction.conf (N,H,W)`。DA3 自己的 GLB 导出就是按 `conf_thresh_percentile`（默认 **40.0**）过滤的，另有天空深度处理、黑白背景过滤、场景尺度归一化、`num_max_points`（默认 1e6）下采样 |
| **直接预测 depth，而非 disparity** | 官方对 `DA3MONO-LARGE` 的说明：*"Unlike disparity-based models (e.g. Depth Anything 2), it directly predicts depth, resulting in superior geometric accuracy"* |
| **多视图一致** | 同一模型一次前向处理 N 张，深度在同一世界里自洽 → 可以做跨视图校验 |
| **度量尺度** | `DA3METRIC-LARGE`（Apache-2.0）输出米制 |
| **处理分辨率与输入解耦** | `process_res` 默认 **504**，`upper_bound_resize`（长边缩到 504）。官方例子：1200×1600 → 378×504 |

**没改的：**

> **输出仍然是 H×W 的深度图，"1 像素 1 点"这个架构没变。**

所以用户的观感依然会成立——但**原因不是点数，是采样方式**。DA3 把点数从"原图像素数"降到了"504² × 视图数"（6 张图约 114 万），这确实变少了，但**降低点数不会提高质量**。

### 1.3 真正的补偿机制，全在管线里，不在模型里

这是本文最重要的一节。五个手段，按性价比排序：

| # | 手段 | 做法 | 效果 | 成本 |
|---|---|---|---|---|
| 1 | **conf 分位过滤** | 丢掉 conf 最低的 30~50% | 立刻去掉最脏的区域 | 3 行 |
| 2 | **多视几何一致性检查** ⭐ | 把视图 A 的深度按位姿重投影到视图 B，与 B 的深度比较，重投影误差大的判为外点 | **经典 MVS 的黄金标准**，能同时压掉 flying pixels 和错误表面 | ~50 行，需 pose |
| 3 | **深度边缘断裂** | 相邻像素深度跳变超过阈值 → 判为遮挡边界，边界两侧剔除 | 消除"拉丝" | ~20 行 |
| 4 | **表面重采样** ⭐ | 不是按像素留点，而是 voxel 化后每格留一个代表点；或用 blue-noise / Poisson-disk 按**表面面积**采样 | 点数由"面积 × 目标密度"决定，与图像像素无关 | ~80 行 |
| 5 | **分层深度 LDI** | 单图专用，见第 3 节 | 补出被遮挡区域 | 需小 inpainting 模型 |

参考：[Learning-based MVS 综述](https://arxiv.org/html/2408.15235v3) 对 geometric consistency filtering 的定义——*"the consistency of depth estimations are measured among multiple views"*。

**手段 2 和 4 是同一次投入、两处收益**：几何一致性检查既提点云质量，又直接服务户型提取（第 4 节）。

**目标点数**：10 万 ~ 50 万（浏览器 60fps 的上限），不是 300 万。

## 2. 高斯渲染能用吗？—— 先分清三件事

高斯渲染**不是"把点云渲染得更好看"，它是换一种表示**。3DGS 的 primitive 是"带协方差的各向异性椭球 + 不透明度"，天然有体积、有软边、能填补间隙。而单目深度管线**不产生这些参数**。

| 路线 | 做什么 | 可行性 | 成本 |
|---|---|---|---|
| **A. 真 3DGS** | 用模型的 GS head 直接出高斯 | ❌ **不可行**。DA3 的 GS head 只在 `DA3-GIANT`(1.15B) / `DA3NESTED-GIANT-LARGE`(1.40B)，**CC BY-NC 4.0 非商用**，且 8GB 装不下 | — |
| **B. 点 → 高斯（伪生成）** | 每个点用深度/法线估一个扁平协方差：沿表面切向拉长、法向压扁 | ⚠️ 可行，是常见 hack | ~100 行 + 一个 shader |
| **C. billboard / splat 风格渲染** | 把点渲染成有软边、有深度衰减、带颜色渐变的圆片。**不是真 GS**，只是像 | ✅ **最推荐先做** | three.js 一个 shader，~1 天 |

**结论：先做 C，不够再上 B，别碰 A。** 你要的"点云风格"效果，90% 在 C 这一层就能拿到。

### 2.1 点云风格渲染（NPR）本身是个研究方向

有正式的综述：[A Survey on Non-Photorealistic Rendering Approaches for Point Clouds](https://www.computer.org/csdl/journal/tg/2025/09/10541081/1Xlt57WokwM)（IEEE TVCG 2025），以及 [NPR of 3D Point Clouds（2024）](https://www.scitepress.org/publishedPapers/2024/125758/pdf/index.html)。可借的手法，全部是 fragment/shader 级，**零模型、零显存**：

| 手法 | 实现要点 | 观感 |
|---|---|---|
| 深度衰减点大小 | `gl_PointSize = size * (1.0 / -mvPosition.z)` | 空气透视，最有效的一招 |
| 软边圆片 | `discard` 圆外 + `smoothstep` 边缘 alpha | 去掉"方块扎人"感 |
| 颜色向背景色插值 | 按归一化深度 mix 背景色 | 远景自然褪掉 |
| 色阶分层 / posterize | 颜色量化到 4~8 阶 | 版画/丝网印风格 |
| 抖动 / 半调 | ordered dithering | 复古印刷感 |
| 轮廓描边 | 深度不连续（sobel on depth）+ 加深 | 插画/漫画感 |
| 笔触形状 | `InstancedMesh` + 各向异性 quad | 笔触/油彩感 |

**实现注意**：`gl_PointSize` 在部分驱动上有上限（64/255），且无法各向异性。要笔触感必须用 `InstancedMesh` + 自定义 quad，不要用 `THREE.Points`。

### 2.2 除高斯之外，风格化渲染的完整谱系

#### 先摆正位置：高斯只是"splat 谱系"的最后一环

```
点 → 圆点 → 屏幕空间 splat → EWA splatting / surfel 圆盘 → 3DGS 高斯
        （Zwicker 2001/2002  ·  Pfister 2000 "Surfels"）
```

而且**风格化并不与高斯竞争**——高斯自己也能被风格化：[Gaussian Splatting in Style](https://arxiv.org/html/2403.08498v2)、[GAGS（SPIE 2026）](https://www.spiedigitallibrary.org/conference-proceedings-of-spie/14351/143511Z/GAGS-graph-guided-adaptive-Gaussian-splatting-for-scene-stylization/10.1117/12.3119870.full)。

所以正确的问题不是"除了高斯还有什么"，而是**"在哪一层做风格化"**。共三层：

| 层 | 决定什么 | 例子 |
|---|---|---|
| **L1 基元层** | 一个点被画成什么形状 | 圆点 / 软片 / EWA 圆盘 / 笔触 / 粒子 |
| **L2 风格层** | 整个画面是什么画风 | 点画 / 半调 / 排线 / 描边 / 版画 / 像素 |
| **L3 时间层** | 动起来是什么质感 | 沸腾线 / 抖动换序 / 笔触跟随 |

#### L2 风格层：七种，都有研究支撑或可自实现

| 风格 | 核心做法 | 参考 | 成本 |
|---|---|---|---|
| **点画 Stippling** ⭐ | **点密度表达明暗**，而不是颜色。暗处密、亮处疏 | [Interactive Stipple Rendering for Point Clouds](https://dspace.zcu.cz/bitstreams/386666f4-28c6-4532-b560-59da98ecee69/download)；经典算法 Weighted Voronoi Stippling（Secord, NPAR 2002） | 中 |
| **排线 Hatching / 交叉排线** | 按明暗铺排线纹理，可 art-directed | [Art-directed Hatching of 3D Point Clouds](https://pdfs.semanticscholar.org/5052/b24ab920aa84a47755481c17b9ee61b940c8.pdf)（扩展 X-Toon） | 中 |
| **笔触基元 Stroke-based** | 每个 splat 画成一个笔刷笔触，两种混合模式 | [Stroke-based splatting](https://link.springer.com/article/10.1007/s00371-017-1420-7)（The Visual Computer 2017） | 中高 |
| **半调 / 网点** | 屏幕空间网点，或 manga 网点纹理 | 通用图形学 | 低 |
| **描边 + 分层平涂（Toon）** | 深度不连续处描边 + 颜色量化分层 | 线描理论：Hertzmann；[Suggestive Contours](https://gfx.cs.princeton.edu/pubs/DeCarlo_2003_SCF/)（DeCarlo, SIGGRAPH 2003） | 低 |
| **版画 / 丝网印** | posterize + duotone + 有序抖动 | 通用 | 极低 |
| **像素 / voxel 风** | voxelize 后再渲染 | 通用 | 中 |

#### L1 基元层：五种基元

| 基元 | 说明 | 何时用 |
|---|---|---|
| `THREE.Points` 圆点 | 最便宜，一个 draw call | 快速预览、百万点 |
| 软边圆片 | `discard` 圆外 + `smoothstep` 边缘 | **通用默认** |
| EWA splat / surfel 圆盘 | 椭圆核，按法线定向、按深度缩放 | 要"连续表面"感 |
| 各向异性 quad（`InstancedMesh`） | 任意朝向，可贴笔刷/网点纹理 | 笔触、水彩 |
| 粒子（加法混合） | 半透明叠加 | 星云、发光、梦境感 |

#### L3 时间层：动图才有意义

| 手法 | 做法 | 效果 |
|---|---|---|
| **沸腾线 boiling** | 每 2~3 帧重新计算笔触/抖动相位 | **手绘动画感——插画动图最有效的一招** |
| 抖动换序 | blue noise 每帧换种子 | 复古印刷的动态感 |
| 笔触跟随 | 笔触朝向跟随相机或法线 | 油画感 |

#### 一个工程分野：屏幕空间 vs 世界空间

| | 屏幕空间（后处理） | 世界空间（每点属性） |
|---|---|---|
| 做法 | 拿到 color + depth + normal buffer，再风格化 | 预处理时给每个点算风格属性（笔触方向、网点相位） |
| 优点 | **可叠在任何渲染结果上**（点云 / 3DGS / 普通渲染都行），1~2 天就能出 | 视角转动时风格稳定 |
| 缺点 | 视角变化时风格会"游动"（shower-door effect） | 每点多几个 attribute，要预处理 |

**先做屏幕空间后处理**，因为它复用在所有内容上，而且是纯 shader，零显存。

#### 点云独有的一件特权

> **点密度本身就是风格参数。**

用密度表达明暗（点画的本质），这在 mesh 上做不到，因为 mesh 的采样密度由拓扑决定。点云的"点数"是一个**免费的艺术控制量**——这也是为什么"点云风格"最自然的落点是点画（stippling），而不是别的。

#### 最便宜的一招（约 10 行，先验证观感）

```
取一张 blue noise 纹理 → 采样 → if (noise > luminance) discard;
```

一步就得到点画 / 半调的全部观感，**不需要任何模型**。配合每帧偏移采样相位，沸腾线效果也一起来了。先用这个验证"风格方向对不对"，再决定要不要投入做真正的 stippling / hatching。

## 3. 单张插画 → 点云：能做，但不是 DA3 的主场

### 3.1 三个必须知道的坑

1. **OOD（分布外）**。深度模型训练在真实照片上。插画是分布外输入，结果通常是"看起来有体积感但几何荒诞"——大片平坦、背景被当成无限远、边缘夸张。**能用，但要按"美术体积感"而非"真实几何"设定预期。**
2. **单图只有一面**。转动就穿帮（同 1.1 病灶 2）。
3. **点密度与线条**。插画的平坦色块反投影后是大片共面点，而线条边缘会炸出飞点。

### 3.2 正确路线：LDI（分层深度 + 补洞），不是 GS

单图 → 可动 3D 的经典答案是 **Layered Depth Image**：

> [3D Photography using Context-aware Layered Depth Inpainting](https://shihmengli.github.io/3D-Photo-Inpainting/)（Shih et al., CVPR 2020）
> 用带显式像素连通性的分层深度图作表示，通过 context-aware 的**颜色与深度 inpainting** 合成被遮挡区域，从而能在单张照片上产生合理的视差。

它解决了 1.1 病灶 2（只有一面）——把被遮挡部分"猜"出来，分层存在后面。

**关键：它用的 inpainting 网络很小**（LaMa 级别，~200MB，CPU 都能跑）。这不是"SD 模型"，不违背你放弃 SD 的决定。

### 3.3 判断

| 项 | 结论 |
|---|---|
| 技术可行 | ✅ |
| 需要新模型 | ⚠️ 需要一个小 inpainting（LaMa 级），不是零模型 |
| 8GB | ✅✅ 单图，比多视图更轻 |
| 与 v1 复用 | ❌ 只复用"深度"这一层，后面完全不同 |
| 商业 | 弱（内容/玩/展示），不是需求 |
| 风险 | **没有下游**——产出的是"好看的动图"，不是可用的模型 |

**建议：把它当支线/展示，不当主线。** 它和 A 方向共用一个深度引擎，所以不冲突，但不要同时开工。

## 4. A 方向（户型/尺寸）具体怎么做，以及难点在哪

### 4.1 分四个阶段，每阶段独立可验收

| 阶段 | 产出 | 难度 | 估时 | 验收 |
|---|---|---|---|---|
| **A0 俯视投影图** | 拟合地面 → 把点投影到地面平面 → 出 2D 俯视图 | ★ | **1 天** | 人眼一看就知道户型对不对 |
| **A1 房间尺寸数字** | 面积 / 长 / 宽 / 层高 | ★ | 0.5 天 | 对比卷尺，误差 < 5% |
| **A2 轮廓多边形 + SVG** | 2D 上 RANSAC/Hough 找线段 → 正交吸附 → 闭合 → 多边形 → SVG | ★★★ | 2~3 天 | 多边形与 A0 的图对得上 |
| **A3 门窗 / 多房间 / DXF** | 开口检测、房间分割、图层化导出 | ★★★★★ | v2 |  |

**关键判断：A0 + A1 已经能拿到 80% 的价值。** 大多数场景（"这房间 12.3 平，长 4.1 宽 3.0"）不需要 CAD 级平面图。**不要一上来就做 A2。**

### 4.2 真正的四个难点

**难点 1：重力方向（最容易崩）**

DA3 的世界坐标系是"以参考视图为原点"的，**up 方向是任意的**。找到"哪边是上"要靠几何自己推（法线直方图投票 / 最大平面 RANSAC）。

为什么这一步这么关键——一个具体数字：

> 地面法线偏 **2°**，墙角在 2.5m 高处的俯视投影会横移 **2.5 × tan(2°) ≈ 8.7 cm**；整面墙的上下沿错开量不同，观感就是"墙是斜的"。

而 2° 的误差在单目深度里是很正常的。**这一步错了，后面全歪。**

**难点 2：大平面在单目深度里会弯曲**

这也是为什么 A1（面积）比 A2（轮廓）便宜得多：面积只需要平面拟合 + 投影 + 多边形面积，弯曲被平均掉了；而轮廓要求每条墙线平直，弯曲会直接变成波浪线。

**难点 3：点云不完整**

只拍 4 个角度，很可能整面墙没拍到 → 轮廓不闭合。这是**数据问题，不是算法问题**。除了引导用户"绕一圈"没有好办法。

**难点 4：门窗开口**

这是独立课题（需要检测空洞 + 分类成门/窗）。明确推到 v2。

### 4.3 三个降难度的杠杆

| 杠杆 | 做法 | 收益 |
|---|---|---|
| **半自动 > 全自动** ⭐ | 在浏览器里让用户点两下：标"这块是地面"、标"这个角是直角"。全自动失败的场景，人一眼就能纠 | **成本降 10 倍** |
| **规则化只做 90° 吸附** | 不做任意角度、不做斜墙 | 省掉最复杂的拟合 |
| **多视一致性压噪声** | 就是 1.3 节的手段 2 | 一次实现，两处复用 |

### 4.4 参考

- [RoomFormer](https://github.com/ywyue/roomformer)（CVPR'23）：3D 扫描 → 平面图的多边形预测
- [2D Floorplan CAD Generation from 3D Point Clouds](https://github.com/joyjo/to-generate-2D-floorplan-CAD-from-3D-point-clouds) + [论文](https://www.mdpi.com/2076-3417/10/8/2817)：Manhattan-World 假设下的墙/地/顶平面检测 → CAD

⚠️ **重要差异**：这些工作都吃**稠密激光/扫描点云**。我们吃的是单目多视图的稀疏深度，精度差一截。所以不能直接套，只能借思路——而且必须先用 A0 验证"我们的输入够不够"。

## 5. 两条线的关系

|  | **A 户型/尺寸** | **插画点云风格** |
|---|---|---|
| 目标 | 准确 | 好看 |
| 输入 | 多图真实照片 | 单张（插画） |
| 复用 v1 主链路 | **100%** | 只有 depth 那一层 |
| 需要新模型 | ❌ | ⚠️ 小 inpainting（LDI） |
| 8GB | ✅ | ✅✅ 更轻 |
| 主要风险 | 自动化程度 / 精度 | 没有下游 |
| 商业价值 | 中（设计/房产/装修） | 低（内容/玩） |
| 定位 | **主线** | **支线/展示** |

**结论：A 是主线，插画点云是支线。两者共用深度引擎，不冲突，但不要同时开工。**

## 6. 最小验证顺序（建议）

| 步骤 | 内容 | 估时 | 决策点 |
|---|---|---|---|
| 1 | DA3 单图跑通，看深度质量 | 1 天 | 质量能否接受 |
| 2 | + conf 过滤 + 边缘剔除 + voxel 重采样 | 0.5 天 | 点数能否控到 50 万内且观感可接受 |
| 3 | 多视图 + 几何一致性检查 | 1 天 | 能否补洞、压掉飞点 |
| 4 | **A0 俯视投影** | 1 天 | **户型能不能看出来——这是 A 方向的生死线** |
| 5 | 二选一：做 A1/A2，或转去做插画点云 | — | — |

**第 4 步是整个 A 方向的 go/no-go 关卡。** 它只要 1 天，却决定了后面两周要不要投。

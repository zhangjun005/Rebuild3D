# web — illust3d 渲染层

浏览器里的风格化点云渲染器。**渲染只在浏览器**（[docs/selection.md](../docs/selection.md) §4.3），
风格规格见 [docs/rendering-styles.md](../docs/rendering-styles.md)。

第一阶段实现的是 §7 的第一套预设「**点画印刷**」：
L1 软边圆片 + L2 blue noise 点画 + L2 深度描边 + L3 沸腾 + L4 空气透视 / 单色墨点。
A 阶段加上**循环动图导出**（WebM 录制 / 帧序列 PNG / 无缝自检）。

技术栈：**Vite + TypeScript（strict）+ three.js，无框架**。shader 全部独立成 `.glsl` 文件，用 `?raw` 导入。

## 基准视角 = 正面（C1，接真实深度点云前必改）

深度图反投影出来的点云，约定是 **+Z 朝观察者 / +X 右 / +Y 上**（[docs/selection.md](../docs/selection.md) §4.4）。
所以「这幅插画本来的样子」就是 **正对 -Z 的正面视角**（azimuth = 0, elevation = 0）。
从 3/4 视角看插画点云，等于**把画斜过来看** —— 即使只有 15°，画面的"端正感"也没了。

- 取景基准 = 正面：相机在 `+Z` 看向 `-Z`，摆动围绕这个基准
- 测试 fixture（球+立方体）的 3/4 视角保留成调试开关：
  - UI：面板「3/4 基准视角（仅调试 fixture）」
  - URL：`?baseView=threeQuarter`（也接受 `3q`）
  - `raw` 预设默认打开（它就是给 fixture 看立体感用的）
- 对比图：`web/.shots/40-baseview-front.png` / `41-baseview-three-quarter.png`
- 附带修掉的一个坑：原来是「仰角下限 4° + 极角上限 88.6°」按测试场景的"地面"卡死的；
  正面基准的极角本来就是 90°，这样会把摆动卡成单边。现在改成绝对范围 [-80°, 86°] 的防翻转保护，
  俯仰限位按基准对称设置。

**为什么正视角对插画是对的**：主体是一块平板，正面看才是"一张画"；
3/4 视角下平板的透视压缩 `cos(15°)` 虽然只有 3.4%，但**画面的横平竖直全歪了**，
读者第一眼就会觉得"这是斜着的"。而 3D fixture（球+立方体）需要 3/4 才能看出体积。

## 深度符号：Go 输出 z = -d，渲染层用标准 +Z 相机（地基级 bug 的定稿）

单目深度 d 是**距离**（越大越远）。Go 侧反投影输出 **z = -d**，所以点云的 z 越大越靠近观察者，
渲染层相机在 **+Z** 沿 -Z 看（three.js 默认朝向）就是「正对画面」。

> 历史：Go 曾经输出 z = d（远处 z 大），渲染层为了"看起来对"把相机放在 -Z——两端各自合理、
> 合起来是**双重取反**。症状是雾、深度上墨、视差三条同时反向（空气透视把主体洗白、
> 墨上到背景、背景比主体动得多）。现在符号统一在 Go 侧，渲染层用标准相机。
> **两边只能有一边翻**：将来若要改，必须同时改回去。

验证方式（别靠"看着好不好看"——反了也好看）：在相机空间量深度。

| 数据 | 主体（画面中心） | 背景（画面外围） | 相机空间深度 |
|---|---|---|---|
| 新约定 z=-d | z = **-0.449** | z = -0.859 | 主体 **5.75** < 背景 6.14 ✓ 主体更近 |
| 若取反（旧） | z = +0.483 | z = +0.861 | 主体 4.78 > 背景 4.43 ✗ 主体更远 |

（同一个 ILC1 文件、同一相机，只把 z 取反：`83-equiv`/`84-equiv-raw-bytes`/`85-equiv-negated` 三张对照。）
## 点云档位：20 万 / 40 万 / 60 万（实测）

同一张图、同机位、墨量按深度 + 铜版画：

| max_points | workRes | 点数 | ILC1 | 传输 body | 解析入库 | 推理 | 几何 | fps |
|---|---|---|---|---|---|---|---|---|
| 200,000 | 775 | 200,000 | 2.86 MB | ~35 ms | 17 ms | 827–865 ms | 258–268 ms | 144 |
| 400,000 | 1095 | 400,000 | 5.72 MB | ~35 ms | 27 ms | 875–961 ms | 319–348 ms | 144 |
| 600,000 | 1342 | 600,000 | 8.58 MB | 38 ms | 38–39 ms | 697–1034 ms | 393–416 ms | 144 |

**帧率完全不是约束**（三档都是 144fps，单 draw call 的顶点开销在 60 万级仍远未饱和）。
约束是「点数越多 → 平坦区越密 → 越像点云照片、越不像版画」：
`edgePointRatio` 200k 是 0.1975（受限于边缘像素数），600k 降到 0.1537（多出的点全分到平坦区）。
所以默认档位应偏低（点云模式的卖点是**视差**，不是细节）：铜版画+按深度三档肉眼几乎无差别，
点画档 40/60 万细节更多但背景更密、figure-ground 反而变弱。

## 彩色点画（产品主路径）：保留每点颜色，印刷质感做叠加层

**核心发现**：点云里本来就有线稿——它藏在**每点的颜色**里（颜色取自原图像素）。
「单色 + 亮度→点密度」这条路会把它抹掉：白裙主体亮度高 → 几乎不给点 → 主体消失。

所以新增 `color-print` **彩色点画**预设（默认预设）：

| 参数 | 作用 |
|---|---|
| `colorMode` | 1 = 保留原色路径。点只带颜色；**点密度不再由亮度决定** |
| `colorPosterize` | 色调分离级数（默认 5）——"像印刷品"的关键一步 |
| `colorHalftone` | 屏幕空间网点叠加强度（默认 0.5，叠在颜色上，不参与点生成） |

实现（最小改动，没动管线结构）：
- `applyParams` 里：彩色路径把 `uStipple` / `uMono` / `uFogAmount` 归零（前两个是旧单色路径的开关，
  雾会把颜色洗成纸色），点略放大 ×1.35 盖住纸缝，深度描边强度降到 0.18（线稿已经在颜色里）。
- **印刷质感全部在合成 pass 叠**（`post-edge.frag.glsl` 的 `printify()`）：
  色调分离 → 屏幕空间网点（暗部叠墨）→ 纸纹（低频纸色 + 高频颗粒）。
- 单色墨量路径原样保留：`stipple-print` / `halftone-manga` / `engraving` / `ink-edge` 预设
  都显式 `colorMode: 0`，铜版画/半调照旧可用。

对比（`out/ab-base.ilcl`，20 万点，同机位）：`web/.shots/00-color-print-abc.png`
A 单色铜版画（只剩轮廓）｜B 彩色点画｜C 彩色+强网点。

## 图像模式（对照用，非产品路径）

> **scope 变更（用户定）**：所有渲染都针对**生成的点云**。图像模式因此降为对照/调试——
> 代码保留（它证明了「深度信息缺失」到底损失了什么），但默认关闭，收在面板的
> 「调试 / 对照（非产品路径）」折叠区里。

用户提的「不同插画风格差异很大，为什么不多给几个选项」被拆成了三层：

| 层 | 内容 | 实现 |
|---|---|---|
| 第一层 | **要不要立体** | `渲染模式`：图像模式 / 点云模式 |
| 第二层 | 这幅画该怎么读 | `墨量来源`（按亮度/按局部结构/按深度）+ `主体极性`（自动/亮主体/暗主体） |
| 第三层 | 什么画风 | 预设（点画/半调/铜版画/线描/原色） |

**关键洞察**：点画/半调/排线本质上是 **2D 图像处理**，点云只贡献立体感/视差。
为了立体感，点云模式付出的是深度分辨率的信息损失（4000×4000 → 504×504），线稿全丢。
图像模式**完全不碰深度、不请求 Go**：把原图当纹理贴到全屏 quad，复用同一套合成 pass。
线稿、五官、装饰全部保留，也永远不会被深度质量拖累——它是最强的保底。

- 上传即出图：实测 **238 ms**（纯浏览器，无网络/推理）——现在这是对照路径才走的路
- 三种画风共用合成参数，两种模式切换时画风连续
- 点画在图像模式用**屏幕空间 blue noise**：blue noise 打规则点阵会摩尔纹，打连续图像不会（§8）
- 点云模式没有图像纹理，所以「按局部结构」用**深度梯度**代替亮度梯度（同一套语义）
- 结构来源**不做极性翻转**：结构本身已经是「该上墨的地方」，翻转会变成给平坦区上墨

### 墨量三选修掉了「主次颠倒」

之前墨量按**绝对亮度**：白裙（亮）→ 不上墨 → 消失；粉背景（中调）→ 大量上墨 → 抢戏。
现在默认 **按局部结构**：局部梯度大（线稿/五官/褶皱/头发丝）才上墨，平坦区留纸。
证据：`web/.shots/89-ink-source-compare.png`（按亮度 → 主次颠倒 / 按局部结构 → 主体回来）。

## 真实插画接入（POST /api/infer）

```bash
# Go 服务（端口 18123；8123 被别的进程占了）
go build -o out/illust3d.exe ./cmd/illust3d
out/illust3d.exe -web-dist web/dist          # sidecar 会自动拉起并预热（7~12s）

```

面板顶部「插画输入」：**选择插画…** 或**把图片拖进窗口**。流程：
`GET /api/health` → 没就绪就轮询显示「模型加载中…」→ `POST /api/infer`（multipart，
字段 `image`）→ 响应就是 ILC1 字节 → 零拷贝进 `THREE.Points`。
状态行给出点数 / 深度分辨率 / 推理毫秒 / 几何毫秒 / ILC1 体积。

代理写在 `vite.config.ts`（`server.proxy` + `preview.proxy`，目标可用 `ILLUST3D_GO` 覆盖），
所以前端只请求同源 `/api/*`，不用配 CORS。

### 接真实数据时修掉的四处（都是"为 fixture 写的假设"）

| 问题 | 现象 | 修法 |
|---|---|---|
| 取景留边 `FRAME_MARGIN=0.9` | 真实插画被**裁掉约 10%**（画面边缘没了） | 改成 1.04（留白 4%）；并且相机距离改成**按实际投影点精确套框**（`fitDistanceFromPoints`），包围盒角点是空的会算太近 |
| 点画抽稀用**位置哈希** | 真实点云是**规则网格**（504×504 逐像素反投影），格点哈希相关 → 屏幕上出现条带摩尔纹 | CPU 端生成**每点随机数 `aRandom`**，密度/点画抽稀一律用它 |
| 亮度用绝对阈值 | 白底/浅色插画整片偏亮 → **亮部全成空白纸**、疏密对比消失 | **自动色调范围（auto-levels）**：取点云亮度的 5~95 分位归一化，点画/半调/排线共用 |
| 描边阈值 0.14 | 真实深度是「主体板 + 背景板」硬台阶 → 描边过浓、到处都是线 | 预设默认提到 **0.3**（半调 0.22）；仍可调 |

### 如实说：第一版画面**还不好看**，而且是数据决定的

深度只有「主体一块板 + 背景一块板」，**插画内部的线稿/眼睛/装饰在深度里不存在**。
墨/纸系风格（点画/半调/排线）只能用点的疏密表达明暗，于是：
- 白色主体 = 纸白（留白），背景被网点/排线铺满 → 读起来像**点描剪影**，不像那幅插画
- 三套预设里 **铜版画最好看**（排线把平板压出层次，纸黄/墨褐的 duotone 也帮忙）
- 点画印刷/半调漫画目前都偏「剪影感」

要真正"像插画"，需要把**图像本身的亮度/边缘**也用起来（现在只有逐点颜色 + 深度）：
例如 Go 侧把 504² 的亮度/边缘强度烘进 ILC1（新增属性），或让颜色属性保留更高分辨率的
线稿信息。这属于数据侧配合，不在渲染层能单独解决。

## 相机限位 + 摆动（A2，go/no-go 的后果）

**真实插画的深度只给「剪影 + 平板」，没有主体内部结构**，所以不能 360° 环绕 ——
转到侧面就露馅。于是：

- 环绕改成**来回摆动**（`sin`），不是单向转圈
- 方位角与俯仰角都限制在取景基准的 **±`swayAmplitude`** 内（参数 0~45°，**默认 15°**）
- 俯仰摆幅 = 方位摆幅 × 0.5（只给一点点，避免看到板的上下边缘）
- `swayAmplitude = 0` 时相机锁死在正面（只看平面剪影的用法）
- 手动拖拽会**自动关掉自动摆动**（手和自动运动不打架），且拖拽范围同样受 ±幅度限制
- OrbitControls 的 `min/maxAzimuthAngle`、`min/maxPolarAngle` 都按幅度设置

## 半调漫画（B 阶段）

`halftone-manga` 预设 = §2.4 半调网点 + 粗描边 + 黑白。

**网点放在合成 pass，不放在点材质里**：半调是「对连续调图像做网点分色」，
网屏必须是屏幕空间的连续网格；在每个 2~3 px 的点精灵内部做网点会把点切碎，
点与点之间没有连续性，读起来是噪点而不是网点。所以颜色 pass 先把点云画成一张
连续调图像（`stipple = 0`，小点径），合成 pass 再对它做网点化
（`styles/halftone.frag.glsl`）。

```
vec2 g = rot(fragCoord + 抖动偏移, screenAngle)
vec2 cell = fract(g / cellSize) - 0.5
float r = sqrt(1.0 - pow(lum, densityGamma)) * 0.5   // 半径 ∝ sqrt(覆盖率)，印刷公式
dot = 1 - smoothstep(r - 0.07, r + 0.07, length(cell))
颜色 = mix(纸, 墨, dot)，只对「有几何覆盖」的像素做（用深度图判断，背景保持纯纸）
```

- 参数：`半调网点`（强度 0~1，>0 时切到半调合成 pass）、`网点大小 px`（3~14，默认 8）、
  `网屏角度 °`（默认 45，印刷常用 15/45/75）
- **§3 抖动换序**：网点网格按沸腾相位整体平移（< 一个 cell）→ 网点重排的手绘/印刷感
- 半径系数必须是 0.5：用 0.72 会让中间调就糊成实黑（网点彼此粘连），0.5 才是完整调子范围

## 铜版画（C2）

`engraving` 预设 = §2.2 排线 + posterize + duotone（纸黄/墨褐），无时间层（§7 铜版画）。

排线**同样在合成 pass** 做（理由和半调完全一样：排线是对连续调图像做网屏处理）。
`styles/engraving.frag.glsl`：

```
tone     = pow(lum, densityGamma)
quantized= posterize(tone, levels)                     // 4 档左右
ink      = max over j of  hatch(angle + j*45°, spacing*~0.9^j) * step(quantized, threshold_j)
         + step(quantized, 0.06)                       // 最暗一档压成实墨
颜色     = mix(纸黄, 墨褐, ink * 几何覆盖)
```

- 层间角差固定 **45°**（金属版画传统；30° 会互相拍频出摩尔纹）
- 线宽 = 间距的 36%（再粗就连成网格，失去"线"的读感）
- 参数：`铜版画排线`（强度 0~1）、`排线层数`（2~4）、`排线间距 px`（3~12）、
  `排线角度 °`、`色阶数`（3~5）
- duotone 两端是普通参数：`背景/纸色` 与 `墨色`（新增），任何风格都能用

## 导出 PNG（只出图片）

面板底部只有一个输出区：**导出尺寸**（当前视口 / 1080×1080 方图 / 1920×1080）+ **导出 PNG** 按钮。

- `canvas.toBlob('image/png')` → 下载；导出时临时切到目标尺寸渲染一帧
  （pixelRatio 强制 1，绘图缓冲就是目标像素数），导完立刻恢复视口尺寸与相机。
- 文件名带预设与关键参数，**不带时长**：
  `stipple-print_g1.3_d0.9_p2.36_e1_par4_1080x1080.png`
  （`g`=明暗曲线 `d`=点画强度 `p`=点大小 `e`=描边强度 `par`=视差幅度% / 旋转模式则为 `sw`=摆动幅度°）
- 自动化里可以直接拿 Blob：`await window.illust3d.exportPng({width:1080,height:1080})`

## 自适应（真实点云不等于测试点云）

`Viewer.setCloud()` 会按新点云重算所有和尺度相关的量，**不写死任何场景常量**：

| 量 | 怎么定 |
|---|---|
| 相机目标点 | 包围盒中心 |
| 相机距离 | `核心半径 / sin(fov/2) × 0.9`；核心半径 = 到中心距离的 **75 分位**（不被大片地面/背景点的长尾拉飞） |
| 相机 near / far | 由取景距离推 |
| `uPointSize` 的参考视距 `refDepth` | `取景距离 × 0.91` → 换尺度后点的屏幕大小不变 |
| 空气透视 / 描边归一化深度区间 | `refDepth` 的 0.57 / 1.82 倍 |
| 点大小 | 估算屏幕点间距：`间距 ≈ 对角线 / sqrt(点数)` → `点大小 ≈ 间距 × 0.5`（clamp 1.2~8 px） |
| 深度 pass 的点放大 | 固定 4×（点大小已随间距自适应，所以覆盖率不塌） |

实测（`web/.shots/12~15-adaptive-*.png`）：

| 输入 | 点数 | 核心半径 | 相机距离 | 自适应点大小 |
|---|---|---|---|---|
| 原始 | 118,401 | 1.98 | 4.97 | 2.49 |
| 均匀抽稀 | 59,200 | 1.98 | 4.97 | 3.53（×1.41） |
| 再抽稀 | 19,733 | 1.98 | 4.97 | 6.09（×2.44） |
| 尺度 ×5 + 平移 | 118,401 | 9.90 | 24.87（×5） | 2.49（不变） |

## 渲染管线（4 个 pass）

```
1. 深度 pass   点云 → HalfFloat RT，写归一化线性深度（背景 = 1.0 = 最远）
               点放大 4× 封住点间隙；**圆形 discard**，否则方形 tile 会被描边描成方框
2. 平滑 pass   5×5 双边（以中心为参考 + 条件性填洞）→ 干净、保留台阶的深度图
3. 颜色 pass   点云 → 纸色底 RT（软边圆片 + 逐点点画 + 空气透视 + 墨点）
4. 合成 pass   色彩 + sobel 深度描边（+ 极小 Laplacian 补刀）+ 暗角 + 纸颗粒 → 屏幕
```

为什么深度单独一遍、不用主 pass 的 depth buffer：

1. 需要用 HalfFloat 存**归一化线性深度**，8 位会带出条带 → 描边闪（§9）；
2. 点云深度有洞，可以在深度 pass 里把点放大封洞，而不影响画面；
3. **描边不随「点数密度」塌陷** —— 密度调低时线仍然连续，这是美术控制。

## 几个实现决定（和规格不完全一致的地方）

- **点画用「逐点哈希」而不是 §8 的屏幕空间 blue noise**。实测：屏幕空间噪声采样在
  **规则点阵**上会拍频出摩尔纹（测试球面是 Fibonacci 点阵，间距 ~5 px，blue noise cell 2.5 px，
  拍出整片斜向条纹，球面被纹上假纹理）。这是采样定理问题，调参数消不掉。
  §2.1 列的路线二「逐点抖动」正是为此：每点用自己的确定性哈希做保留决策 → 与屏幕无关、
  转动不游走、无摩尔纹、3D 稳定。blue noise 纹理仍然保留并使用：L4 纸颗粒（合成 pass），
  后续半调 / 抖动换序（§3）也用同一张图；生成脚本照 §8 要求自己写。
- **密度 = 1 − 亮度**（暗处点密，§2.1 原文）。注意 §8 的 10 行起手式是 `n > lum` 才 discard
  （亮处留），那是屏幕空间抖动「提亮」的写法；做成点云点画时方向要反过来，
  否则暗部反而空掉。
- **单色墨点 = 统一墨色**，明暗只由疏密表达。若点色也随亮度变化（duotone），
  密度与深浅会双重计数，中间调糊成灰。
- **点数密度用逐点抽稀，不用 `setDrawRange`**。ILC1 的点按「地面 → 球 → 立方体」排列，
  按顺序截断会让密度一降就只剩地面。
- **沸腾相位由「按 60 fps 折算、并对循环长度取模」的逻辑帧计驱动**：换 144Hz 屏也是 10 Hz 重绘，
  而且时间可回绕（§9「GIF 循环跳帧」）。沸腾 = 整个点画的去留按相位置掷一次（手绘重画感）+ 描边微抖。
- **颜色空间**：关闭 `ColorManagement`、`outputColorSpace = LinearSRGBColorSpace`，
  全链路在显示空间计算。着色器是风格化不是物理渲染，避免两次 8 位量化与意外的 gamma。

## 已知问题 / 下一步

- 描边在点很稀的轮廓上会有 ~1 个点距的锯齿（手绘感，也可当 feature）；想要更直的线，
  下一步可以做深度图的形态学闭运算或多尺度梯度。
- **真实深度点云的深度台阶比 fixture 强得多**（主体一块板 + 背景一块板，中间是硬断层），
  描边会比现在浓很多。接真实数据时先看 `描边阈值`（默认 0.14）要不要提到 0.2~0.3 把线调柔。
- 还差三套预设：油画（要笔触 quad 基元）、像素立体书（要 voxel/InstancedMesh 基元）、
  梦境星空（加法混合粒子层）。
- 半调现在只有单网屏（一个角度）。真正的彩印是 CMYK 四色四角度（15/45/75/0），需要四个网屏叠加；
  漫画单色用不到，但如果以后要做彩印半调，得在 halftone.frag.glsl 里加四层。
- `gl_PointSize` 上限驱动相关（§9），已 clamp 到 255，大点时应该改 quad 基元。
- 逐点抖动在极低密度下会有轻微团簇（点云本身是规则点阵时更明显），真实深度点云不会。
  注意：把测试点云做「隔 N 取一」抽稀会保留 Fibonacci 子点阵，屏幕上会看到梳状条纹
  （`web/.shots/14-adaptive-20k.png`）——这是合成数据的规则性，不是渲染器问题。
- 掠射面（几乎侧视的窄面）墨点偏密：密度只看亮度，没算法线·视线的掠射因子。已知，待定。
- 点云里真实的空洞（置信度过滤造成）目前靠深度 pass 的 4× 放大 + 5×5 填洞兜住；
  空洞很大时描边会在洞边画出假轮廓，后续可以按「邻域覆盖度」抑制。
